# Alpha.2D.1 read-only Git Changes

The Changes tab inspects the repository at the granted personal workspace root. It shows the current branch (or detached status), staged, unstaged and untracked paths, one-file patches and the latest 25 HEAD commits. Commit details include message, author, date and file changes. Refresh, cancellation and unavailable states use the existing workspace and UI.1 controls. Group filesystem access and all Git and file mutations remain gated.

## Containment and supported layout

The daemon checks the existing native read grant and workspace identity at start and before release. Responses and cancellation bind bot, workspace, generation and operation IDs. A descriptor-relative traversal makes a private temporary snapshot of ordinary regular files and an allowlisted subset of local Git metadata. Mount IDs must match the authorized root. Symlinks, hard links, special files and sensitive workspace entries are never copied. Original repository/system/user config, alternates, hooks and replacement refs are omitted. Local Git reads only the read-only snapshot and host libraries in a non-root Bubblewrap sandbox with no network, inherited environment, credentials, helper paths or prompts. All subprocess arguments are fixed except validated literal file paths and exact commit IDs from the displayed HEAD history. See [Git repository layout](https://git-scm.com/docs/gitrepository-layout), [porcelain status](https://git-scm.com/docs/git-status) and [diff options](https://git-scm.com/docs/git-diff).

The snapshot is limited to 48 MiB, 4,000 entries and 14 directory levels. An inspection has a five-second cooperative deadline, two concurrent slots and 128 KiB of output per subprocess. Subprocesses also have CPU, descriptor and address-space limits. Status and commit file lists cap at 500 entries. An external modification can make an inspection stale or produce an unavailable result. Refresh to rebuild the read view. The read view can reflect changes made while it is collected. Normal completion and cancellation remove scratch data. Abrupt daemon termination can leave a private temporary copy until host cleanup.

The initial scope is ordinary SHA-1 Git repositories with a local `.git` directory at the authorized root. It cannot follow linked worktrees, parent repositories, submodules, alternates, split metadata or partial clones. Repo-configured ignore and attribute overrides are not applied. Inspection can be unavailable for unsupported layouts, unavailable isolation or over-limit repositories. Git, Bubblewrap and prlimit come from the host at fixed paths. Packaged-host support still needs Alpha.3 verification.
